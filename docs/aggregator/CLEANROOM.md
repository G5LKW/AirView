# Clean-room provenance log

AirView is meant to be published under a licence of its maintainer's choosing. It therefore must not contain code derived from GPL or AGPL programs. The ADS-B ecosystem it interoperates with is largely GPL/AGPL: readsb, dump1090 (all forks), tar1090, mlat-client, mlat-server, pyModeS. This log records **where the knowledge in each AirView component came from**, so that anyone can check that AirView reimplements protocols and algorithms from their behaviour, published documentation and papers, and does not copy those programs' code.

This file is the record DESIGN.md points to ("Clean-room rule ... provenance is recorded in `docs/aggregator/CLEANROOM.md`"). Every work package that adds or changes a component touching third-party protocols or algorithms adds an entry (section 4).

---

## 1. The rule

1. **Never copy, translate or paraphrase line by line** code from GPL, LGPL, AGPL or licence-less programs into AirView. That includes porting a C or Python function to Go "in our own style", reproducing its structure, its comments or its distinctive constants table, and copying test vectors from their test suites.
2. **Never link, embed or ship** such programs inside AirView binaries or installers. They may run as **separate, unmodified processes** that the user installs (section 5).
3. **Preferred sources of knowledge**, in this order:
   1. official specifications and standards (ICAO Annex 10 and Doc 9871, RTCA DO-260B summaries, RFCs, the Jetvision wiki for Beast/Radarcape formats);
   2. peer-reviewed papers and textbooks (section 3);
   3. **black-box observation**: captures of the user's own equipment and of unmodified programs talking to each other, their documentation, README files, man pages and command-line help;
   4. permissively licensed code (MIT, BSD, ISC, Apache-2.0, public domain), with attribution where its licence asks for it.
4. **Reading GPL/AGPL source** is a last resort, allowed only to confirm a **fact** (a wire field's meaning, a port number, a convention) that the sources above leave open. The fact is restated in our own words in an AirView doc comment that names the source, and the reading is **logged in section 4** with the fact it established. The engineer does not keep the source open while writing the AirView code for it.
5. **Data is not code**, but it has licences too. Datasets (aircraft databases, geoid grids, terrain tiles) are recorded in section 6 with their licence and the attribution AirView shows.
6. Algorithms, mathematical methods, protocol facts and interoperability interfaces are not protected by copyright; their **expression** is. Keep AirView's expression independent: our own names, structure, decomposition and comments, written from the description.

### Reviewer checklist (use on every change to `internal/feed`, `internal/modes`, `internal/ingest/*`, `internal/mlat/*`, `internal/refdata`, `internal/uplink`, `internal/avf`, `cmd/airview-feeder`, `deploy/feeder/*`)

- [ ] The change cites its sources in the package doc or the function comment.
- [ ] No identifiers, comment text, table layouts or control flow mirror a GPL/AGPL implementation (if the reviewer knows the upstream code, compare structure, not just names).
- [ ] Constants that are facts (ports, escape bytes, bit positions, physical constants) are fine; tuning tables and heuristics taken from a GPL program are logged as an open item (section 7).
- [ ] Test vectors are generated by AirView's own simulator (`internal/sim`, `internal/sim/simnet`), taken from standards or papers, or captured from the user's own equipment; never copied from a GPL test suite.
- [ ] No GPL program is bundled, downloaded silently or linked; installers only **offer** to run upstream installers as separate programs.
- [ ] A section 4 entry exists for the change.

## WP-K-clock (phase 2): internal/mlat/clock — provenance

2026-11-13.
