## 1. Route lookups

New package `internal/routes`; the engine's old 4096-entry route map is gone.

**Done**

- Callsign hygiene (§2.1): airline-style only, never the registration, test/placeholder callsigns skipped,
  variants `BAW0123`/`BAW101P` with a fusion penalty, alphanumeric EZY/RYR suffixes never stripped.
- Resolution order override -> learned -> standing data -> cached online answer, each with a licence class
  (`open` / `own` / `restricted`).
- Plausibility score (§3.2): detour ellipse per leg, the near-end altitude rule (an airliner at FL380 over its
  "destination" is doubtful; this is the hub-overflight fix), heading term, vertical evidence, states fits /
  uncertain / doubtful / reversed, active leg of multi-stop routes, hysteresis (two consecutive 30-s
  evaluations), progress, remaining distance.
- Fusion (§3.3): softmax over hypotheses plus "other route", priors for override / verify / learned
  (days, age decay) / standing / online / variant, stale-standing penalty, switching needs a 1-logit lead twice.
- ETA (§3.4): great circle plus arrival excess by airport size, cruise / descent / approach profile, sigma,
  rounded to 30 s; only for P >= 0.8 and < 1500 NM.
- Learner (§3.6): every closed flight becomes a leg row (`routes_leg`); departure / arrival tiers T1/T2/T3,
  L1/L2/L5 from the existing airport guess; observations in `routes_obs` (both-end legs with confidence >= 0.7),
  time decay (21 d), IATA-season down-weighting, Dirichlet posterior with the standing route as prior,
  promotion at >= 2 days / P >= 0.8 / seen within 14 d, `stale_standing` at >= 3 days / P >= 0.85 with T1/T2/L1/L2
  evidence, 120-day prune.
- Overrides (§4): `fixed` / `verify` / `block`, audit log, locked rows from `routes.overrides.csv` in the data
  directory (re-read when it changes).
- Exports: `learned.csv` in the VRS format (P >= 0.9, >= 3 days; licence CC0 in the `X-License` header, as the
  format has no comment lines), `overrides.csv` (round-trips with the file), `legs.csv`.
- Binding decision 1: `navData.autoRefresh` (default on) downloads airports, runways, navaids, countries and
  the standing-data routes at first start and checks them daily at a per-install time of day (hash of host
  name and data directory) with the importer's existing conditional GET; retries after an hour on failure.
  Offline engines never download. `POST /api/routes/refresh` triggers it.
- Binding decision 2: `navData.routes.online` (default on), adsbdb only, server side only, after the callsign was
  received for `stableSec` (45 s) with a position, through the existing limiter (2 s spacing, daily cap
  `dailyCap` 1000, 429 back-off) and cache (24 h / 12 h). User-Agent `AirView/<ver> (+<contact or project URL>)`.
  Answers are `restricted`: removed from the public DTO, from `privacy.StripAircraft` (aggregator public and
  non-network owner views), from the detail endpoint below owner scope in aggregator mode, never written to
  `routes_leg`, `routes_obs` or exports. `/api/navdata/route/{cs}` and `/api/routes/{cs}` never send an online
  request for non-admin callers (this fixes the budget-drain / injection issue of §1). Settings show the privacy
  text and how to switch it off.
- Binding decision 3: learned routes are exported as CC0 (`/api/routes/export/learned.csv`), linked from Settings
  together with the VRS standing-data site for manual submission.
- `AirportByCode`: 3-letter codes try IATA first.
- UI: the detail panel's route block shows the active leg, state chip, confidence, source (with the reason as
  tooltip), progress bar, remaining distance and "ETA hh:mm ±n min"; Settings has a Routes card.
- Performance: live hit path 130 ns, 0 allocations (`BenchmarkLiveHit`; the DTO is rebuilt every 5 s per aircraft).

## 2. TCAS resolution advisories

New package `internal/acas`. A tracker hook (also on sharded trackers) passes every decoded RA report
(DF16 MV, BDS 3,0 in DF20/21, TC28 subtype 2); reports of one aircraft within 30 s form an event with the
advisories in order ("Climb > Increase climb"), sense, corrective/preventive, RAC, multiple threats, threat
identity, position and altitude at the start, message types and RAT. Closed events go to `acas_event` (730 days).
Live: `aircraft.acas` while active -> red ring and "RA <advisory>" label on the map, legend entry. Map layer
"TCAS RAs (24 h)". Alerts page card (24 h / 7 d / 30 d). API `/api/acas/events`, `/api/acas/status`
(owner scope in aggregator mode). The texts say what a report does and does not mean.

Not done: an alert-rule condition for RAs; RAs in the public DTO.

**Tests:** advisory wording for every ARA combination, grouping / gap / termination / live marks / persistence
and query (`internal/acas`); a DF16 RA frame through the real tracker to the hook (`TestACASHook`); server
every-route test.

## 3. Mode S EHS weather

The station already derived winds and temperatures from BDS 5,0/6,0 and BDS 4,4 (vertical profiles). New:

- `met.BuildGrid` / `GET /api/met/grid`: the stored observations of the last N minutes at one flight level on a
  latitude/longitude grid: vector-mean wind (opposite winds cancel), temperature reduced to the level with the
  standard lapse rate, ISA deviation, counts. Nothing interpolated.
- BDS 4,5 hazard reports (turbulence, wind shear, microburst, icing, wake vortex, SAT, pressure, radio height):
  tracker hook -> in-memory log (one per aircraft per minute, last 2000) -> `GET /api/met/hazards`. BDS 4,5 has
  no identifying bits, so these are rare and shown as received, never used in profiles; implausible SAT rejected.
- Map layer "Winds aloft" with an FL100..FL390 selector (arrows towards where the wind blows, dots coloured by
  ISA deviation, labels when zoomed in).

Not done: fronts and forecasting; hazard persistence; a hazards list in the UI (API only).

**Tests:** grid (vector mean, lapse reduction, ISA, band / window / min-obs filters), hazard log thinning and
ordering; tracker / server / engine suites.

## 4. 8K JPEG heat-map export

New package `internal/heatexport`, `GET /api/antenna/heat.jpg` (default 7680 x 4320, `w`, `h`, `q`, `ant`,
`light`, `download`; one at a time), "8K JPEG" button in the map's layer panel. Web Mercator, heat as Gaussian

## 6. Learned flight prediction

New package `internal/flowlearn`. From every fresh real position (1 Hz, live picture) it learns, per 0.1-degree
cell, altitude band and 30-degree heading sector, how traffic turned over the next 30 and 60 s (time-decayed,
half-life 3 h, so it follows the runway in use and current routings). Prediction integrates those turn rates.
Self-correction: every 15 s per aircraft a learned and a straight prediction are made for 30 / 60 s and scored
when the aircraft gets there; the blend weight moves towards the closer method, and the errors are reported.
`GET /api/prediction/learned` (stats), `learned` in `GET /api/prediction/path/{icao}`, and a dotted
"Learned from traffic" line for the selected aircraft on the map.

Measured on a synthetic arrival turn: 60-s error 0.29 km learned vs 2.63 km straight; self-check improvement
66 % (30 s) / 73 % (60 s), weight -> 1. With straight traffic it stays straight.

Not done: blending into the trajectory filter's coasting positions (the live "predicted" positions still come
from the IMM filter alone); persistence across restarts; per-cell weights.

**Tests:** learning and self-correction on a synthetic turn, straight traffic stays straight, empty learner is
dead reckoning, benchmark (390 ns per observation).
